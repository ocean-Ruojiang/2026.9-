# 建模手／论文手任务入口

你们在这里提交需求与必要附件，由项目负责人（用户）决定优先级、执行人和资源。Codex负责检查和通知，收到任务不会自动执行。

| 角色 | 编辑任务清单 | 上传必要附件 |
|---|---|---|
| 建模手 | [modeling/TASKS.md](modeling/TASKS.md) | [modeling/files/](modeling/files/) |
| 论文手 | [writing/TASKS.md](writing/TASKS.md) | [writing/files/](writing/files/) |

## 提交方式
1. 在本人TASKS.md添加一个任务区块，任务ID保持唯一；修改原任务就在原区块更新，勿换ID重复提交。
2. 先把文件上传至本人files/任务ID/目录，并在任务中写仓库相对路径。确保任务和附件都已提交到main分支；PR只有合并后才会被本机检查。
3. 准备好后将状态写为“待调配”。“草稿”不会触发通知。待调配任务内容变更也会通知，通知按内容指纹去重。
4. 项目负责人分配资源后，在原任务填写“负责人决定”并更新状态。两位提交者不代替负责人批准执行。

## 沟通格式
每个任务使用二级标题（##），其后为ID与标题；字段用中文冒号。建模手ID为MODEL-YYYYMMDD-三位序号，论文手为PAPER-YYYYMMDD-三位序号。

```markdown
## MODEL-20260912-001 简短任务标题
状态：草稿
优先级：P1
提交人：建模手
更新时间：2026-09-12 21:00 +08:00
目标：需要解决什么问题
需求：明确要求分析、编程、实验或写作；写清边界
附件：TEAM_TASKS/modeling/files/MODEL-20260912-001/input.csv
验收：输出内容、格式和判断标准
期限：无／具体时间
依赖：无／依赖的任务ID
负责人决定：待负责人调配；提交者不代填批准
```

状态：草稿 → 待调配 → 已分配 → 进行中 → 已完成；也可写阻塞、已取消。优先级P0紧急、P1重要、P2常规。命令及脚本只能作为文字建议，监控程序不会执行附件或任务中的命令。

## 通知和更新频率
本机每3分钟检查一次main分支；发现新待调配任务或其修改后立即尝试桌面提醒，并更新本机监控屏及桌面“GitHub待调配任务.md”。通常延迟不超过一个轮询周期加网络耗时，并非实时推送。机器需要开机、联网且用户已登录；休眠、网络失败及系统通知设置可能影响提醒。监控屏显示最近成功检查时间，失败不会伪装为没有新任务。

这里是任务沟通记录，CURRENT_BRIEF.md仍每10分钟按变化更新。收件箱不自动在Codex对话中发送消息、不自动唤醒现有终端、不自动调配资源。T1每次开始工作先读收件箱。

## 附件与权限
仅上传完成任务必要的文件；尽量给最小输入、明确单位和版本。不要上传密码、密钥、身份认证、个人敏感数据或完整终端日志。当前仓库公开，上传内容会公开且Git保留历史。使用已有仓库写权限提交；没有写权限的人需由仓库所有者邀请，目录创建不会自动授予权限。
